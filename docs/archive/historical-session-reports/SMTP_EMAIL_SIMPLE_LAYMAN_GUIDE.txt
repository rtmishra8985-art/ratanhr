                    WHAT IS EMAIL CONFIGURATION?
═══════════════════════════════════════════════════════════════════════════════

Think of it like setting up a mailbox for your company:

Normal Mailbox:
  - Physical location
  - Address (street, city)
  - Mailman delivers mail there

Email Mailbox:
  - Digital location (SMTP server)
  - Address (email address)
  - "Mailman" (Brevo) delivers emails there

RatanHR needs to send emails. So we need to:
  1. Set up a mailbox (Brevo account)
  2. Tell RatanHR where the mailbox is
  3. Test that emails get delivered
  4. Deploy to your server

═══════════════════════════════════════════════════════════════════════════════

                    STEP 1: CREATE BREVO ACCOUNT (5 MINUTES)

═══════════════════════════════════════════════════════════════════════════════

What is Brevo?
  → Service that sends emails for you
  → Like Gmail, but for applications
  → Free tier: 300 emails/day

How to create account:

1. Go to: https://www.brevo.com/
2. Click: "Sign Up Free"
3. Enter:
   • Your email
   • Password
   • Company name
4. Check your email for verification link
5. Click the link
6. Done! Account is created

What you'll use later:
  • Your Brevo username
  • Your Brevo API key (password for applications)

═══════════════════════════════════════════════════════════════════════════════

                    STEP 2: CONFIGURE .ENV FILE (5 MINUTES)

═══════════════════════════════════════════════════════════════════════════════

What is .env?
  → Settings file that tells RatanHR:
    - Where to send emails (Brevo server)
    - How to login (username/password)
    - What email address to use

Where to find:
  C:\Users\[YOUR_USERNAME]\Downloads\RatanHR_Run8_Final\RatanHR\.env

What to change:

OLD (for testing):
─────────────────
EMAIL_HOST=localhost
EMAIL_PORT=1025
EMAIL_USERNAME=
EMAIL_PASSWORD=

NEW (for production with Brevo):
─────────────────────────────────
EMAIL_HOST=smtp-relay.brevo.com
EMAIL_PORT=587
EMAIL_USERNAME=your_brevo_username
EMAIL_PASSWORD=your_brevo_api_key

Example:
────────
EMAIL_HOST=smtp-relay.brevo.com
EMAIL_PORT=587
EMAIL_USERNAME=b5ef15001@smtp-brevo.com
EMAIL_PASSWORD=xkeysib-abc123def456...

How to edit:
  1. Right-click .env
  2. Select: "Open with" → Notepad
  3. Find EMAIL section
  4. Replace with new values
  5. Save (Ctrl+S)
  6. Done!

═══════════════════════════════════════════════════════════════════════════════

                    STEP 3: TEST LOCALLY (5 MINUTES)

═══════════════════════════════════════════════════════════════════════════════

What is MailHog?
  → Fake email system for testing
  → Runs on your computer
  → Captures emails so you can see them
  → No real emails sent

How to start MailHog:
  1. Double-click: mailhog_windows_amd64.exe
  2. Wait for: "MailHog v1.x.x"
  3. Open browser: http://localhost:8025
  4. You see empty inbox = MailHog is working ✓

How to test email:
  1. Double-click: SEND_TEST_EMAIL_TO_MAILHOG.bat
  2. Wait for: "✅ SUCCESS"
  3. Go back to browser (http://localhost:8025)
  4. Refresh page
  5. You should see email in inbox!
  6. Click to view email content
  7. If you see it = Email system works! ✓

Result: Email system is tested and working locally

                    STEP 4: DEPLOY TO SERVER (20-30 MINUTES)

═══════════════════════════════════════════════════════════════════════════════

You have 2 choices:

CHOICE A: ON-PREMISE (Your own server)
CHOICE B: CLOUD (AWS, Azure, Google Cloud)

═══════════════════════════════════════════════════════════════════════════════

CHOICE A: ON-PREMISE SERVER
───────────────────────────

What is On-Premise?
  → Your own server
  → You control everything
  → Could be: physical server, VM, or private cloud

Simple Steps:

1. Get a server
   - Physical computer
   - OR Virtual machine (Hyper-V, VMware)
   - OR Private cloud
   - Just needs: Docker and internet

2. Install Docker
   Windows: Download from docker.com and install
   Linux: Run: sudo apt-get install docker.io

3. Copy RatanHR to server
   - Copy application files
   - Copy .env file with your credentials

4. Build application
   docker build -t ratanhr:1.0.4 .

5. Start application
   docker run -d --env-file .env -p 8080:80 ratanhr:1.0.4

6. Test
   - Open: http://[SERVER_IP]:8080
   - Login and test password reset
   - Should receive email

Result: Application is running on your server

═══════════════════════════════════════════════════════════════════════════════

CHOICE B: CLOUD SERVER (AWS / Azure / Google Cloud)
────────────────────────────────────────────────────

What is Cloud?
  → Renting server from big companies
  → AWS = Amazon
  → Azure = Microsoft
  → GCP = Google
  → No hardware to buy
  → Pay monthly

Simple Steps:

1. Create account
   - AWS: https://aws.amazon.com/
   - Azure: https://azure.microsoft.com/
   - GCP: https://cloud.google.com/
   - Choose Free Tier

2. Find Container Service
   - AWS: Search for "ECS" or "EC2"
   - Azure: Search for "Container Instances"
   - GCP: Search for "Cloud Run"

3. Deploy application
   - Click: "Create Service" or "Deploy"
   - Upload RatanHR image
   - Set environment variables (.env values)
   - Set port: 8080
   - Click: Deploy

4. Get URL
   Cloud gives you: http://yourapp.com
   Or: http://123.45.67.89:8080

5. Test
   - Open: http://yourapp.com
   - Login and test password reset
   - Should receive email

Result: Application is running in cloud

                    TROUBLESHOOTING (SIMPLE)

═══════════════════════════════════════════════════════════════════════════════

PROBLEM: Email not being sent
SOLUTION:
  1. Check internet connection (working?)
  2. Check .env file (values correct?)
  3. Check server is running (docker ps shows container?)
  4. Check firewall (port 587 allowed?)
  5. Restart application
  6. Check logs for errors

PROBLEM: Email sent but not received
SOLUTION:
  1. Check email address is correct (no typo?)
  2. Check spam/junk folder
  3. Wait 5-10 minutes (sometimes slow)
  4. Try different email address
  5. Check Brevo account status (logged in?)

PROBLEM: Authentication failed error
SOLUTION:
  1. Check Brevo credentials (username/password correct?)
  2. Copy exact values from Brevo dashboard
  3. No extra spaces?
  4. Create new API key in Brevo
  5. Update .env with new key
