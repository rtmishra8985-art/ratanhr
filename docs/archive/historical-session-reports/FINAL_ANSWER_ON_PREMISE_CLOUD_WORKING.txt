ON-PREMISE DEPLOYMENT:

  docker build -t ratanhr:1.0.4 .

Step 3: Deploy container
  docker run -d \
    --env-file .env \
    -p 8080:80 \
    --name ratanhr-app \
    ratanhr:1.0.4

Step 4: Test
  curl http://localhost:8080/health
  # Should show: Email SMTP Status = OK

Step 5: Send test email
  Via app UI or API → Email sent via Brevo

Step 6: Verify
  Check recipient inbox → Email arrived ✓

─────────────────────────────────────

═══════════════════════════════════════════════════════════════════════════════
                    WHAT HAPPENS WHEN EMAIL IS SENT
═══════════════════════════════════════════════════════════════════════════════

Development (MailHog):
  1. App calls: emailService.SendWelcomeAsync()
  2. EmailService creates MimeMessage
  3. Connects to localhost:1025 (MailHog)
  4. Sends email via SMTP
  5. MailHog captures it
  6. You view at: http://localhost:8025
  7. ✓ Email visible in inbox (not really sent)

Production (On-Premise or Cloud):
  1. App calls: emailService.SendWelcomeAsync()
  2. EmailService creates MimeMessage
  3. Connects to smtp-relay.brevo.com:587
  4. STARTTLS negotiation happens
  5. Authenticates with Brevo credentials
  6. Sends email via SMTP
  7. Brevo receives email
  8. Brevo routes to recipient's email provider
  9. Email delivered to recipient's inbox
  10. ✓ Real email, really sent
